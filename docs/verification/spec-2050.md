# SPEC-2050 implementation and verification

Implemented and accepted in the native review app on 2026-09-07.

## Delivered behavior

- Preserve the compact attached, detached and HUD conversation layouts while
  applying the new colors and calmer page typography. Context removal changes
  the next message payload. Ask First opens the existing approval configuration.
- Add Home availability modes and local Set aside / Rest for today presentation
  with Restore. These controls do not stop work or change stored business data.
- Persist trace avatar identity through existing profile and ACP adapters.
- Keep document proposals reviewable and protect dirty drafts and external edits.
- Use tinted database selection and scoped dashboard pins, preserving existing
  database views and the Accent Strength preference.
- Reuse current data sources across Graph, Canvas, Activity and workspace views.
- Route Ask through the existing conversation owners and retain exact replies.
- Bind workflow starts, approvals, continuation and independent read-only work
  to immutable execution identity and durable result receipts.

## Operational notes

The frontend test suite imports the Supabase client during setup. A clean
checkout can run it without a private `.env.local` using synthetic values:

```sh
VITE_SUPABASE_URL=http://127.0.0.1:54321 VITE_SUPABASE_ANON_KEY=test-anon-key pnpm test
```

These are test-only values; they do not configure a working desktop database.

The two additive meanwhile migrations are included. They were applied to the
existing verification database after approval. They preserve the protected
receipt ledger; no broader client grant is required. The local migration set
does not recreate the full hosted database; see `supabase/MIGRATIONS.md`.

Read-only workflow sessions require the supported Codex ACP adapter. The native
test used an existing Codex 0.153.4 executable through the review wrapper's
`CODEX_PATH` override. Saved provider/model configuration was not changed.

A claimed side step is not automatically dispatched again after a crash. Output
is durable only after settlement commits; recovery does not invent missing
results. The restart proof intentionally occurred after committed settlement.

Native screenshots, internal work records, raw logs and machine-specific
execution details remain local and are intentionally excluded from this public
repository change. No production app replacement or deployment is part of it.
